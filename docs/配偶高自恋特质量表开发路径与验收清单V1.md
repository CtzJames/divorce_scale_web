# 配偶高自恋特质量表开发路径与验收清单 V1

## 1. 文档用途

本文档用于在“配偶高自恋特质与高冲突婚姻风险自测量表”正式进入 VS Code + Codex 开发前，将前五份底座文件转化为可执行的开发路径、任务拆分、验收清单与 git 收口标准。

本文档承接以下底座文件：

1. 《配偶高自恋特质量表网页端产品与开发方案 V1》；
2. 《配偶高自恋特质量表题目-维度-计分映射表 V1》；
3. 《配偶高自恋特质量表结果分级规则与结果页文案框架 V1》；
4. 《配偶高自恋特质量表网页信息架构与页面文案草案 V1》；
5. 《配偶高自恋特质量表后台与数据库适配方案 V1》。

本文档主要回答以下问题：

1. 新量表第一阶段开发应按什么顺序推进；
2. 哪些任务应先做，哪些任务应后做；
3. 每一批开发的目标、建议改动范围和不做事项是什么；
4. 每一批完成后应如何验收；
5. 哪些节点需要 git 收口；
6. 进入 Codex 前应先让 Codex 做哪些只读检查；
7. 如何避免新量表开发破坏离婚力量表现有稳定功能。

本文档不是：

- Codex prompt 正文；
- SQL 迁移脚本；
- 前端代码实现方案；
- 详细报告文案主档；
- 第二阶段报告开发方案。

后续真正进入开发时，应基于本文档分批输出给 Codex 的具体 prompt。

## 2. 第一阶段开发总目标

第一阶段目标是：

**在现有离婚力量表网页端稳定仓库中，以低耦合方式新增“配偶高自恋特质与高冲突婚姻风险自测量表”前台入口，并完成 Supabase 写入、后台列表识别、后台详情基础展示和 CSV 导出适配。**

第一阶段完成后，应形成以下闭环：

1. 用户可访问 `/narcissism-risk`；
2. 用户可完成 40 题随机顺序作答；
3. 系统可完成反向计分、五维均分、总平均分、四档风险判断；
4. 系统可识别高风险触发题；
5. 用户可查看结果页和五维雷达图；
6. 用户可导出简版结果图 PNG；
7. 用户可提交联系方式；
8. 新量表结果可写入 Supabase；
9. 后台列表能识别、展示和筛选新量表记录；
10. 后台详情页能展示新量表基础结果、五维均分、高风险触发题和原始答案；
11. 后台跟进字段继续可用；
12. CSV 导出包含必要新量表字段；
13. 新量表记录不误进入离婚力量表详细报告逻辑；
14. 离婚力量表现有前台、后台和详细报告功能不受影响。

## 3. 第一阶段开发原则

### 3.1 低耦合新增

新量表开发应以新增文件和小范围适配为主。

优先新增：

- 新路由；
- 新题库配置；
- 新计分文件；
- 新提交 payload 构建文件；
- 新结果页组件；
- 新简版导出卡组件；
- 后台显示映射函数；
- 后台量表类型分流逻辑。

避免：

- 大规模重构离婚力量表主流程；
- 直接把现有 `app/page.js` 改成复杂多量表总入口；
- 把离婚力量表计分逻辑改成通用引擎；
- 为了第二量表提前重构整个后台。

### 3.2 不做完整通用量表引擎

当前只新增第二套量表。

不在第一阶段做：

- 多量表元数据表；
- 统一题库数据库配置；
- 后台题库编辑器；
- 通用量表运行时；
- 通用报告生成器。

### 3.3 不接入新量表深度报告

第一阶段不做：

- 新量表后台 A4 详细报告；
- 新量表移动端长图详细报告；
- 新量表后台 PDF 导出；
- 新量表后台 PNG 深度报告导出；
- 新量表详细报告文案主档；
- 新量表报告内容持久化。

### 3.4 旧功能必须回归

每一批开发后都应至少确认：

- 离婚力量表首页仍可访问；
- 离婚力量表答题与结果页不受影响；
- 离婚力量表写库不受影响；
- 后台离婚力量表记录展示不受影响；
- 后台离婚力量表详细报告、PNG、PDF 导出不受影响。

## 4. 进入 Codex 前的前置检查

在正式让 Codex 修改代码前，建议先开新 Codex 线程并要求其进行只读检查。

### 4.1 只读检查目标

Codex 应先确认当前仓库实际结构与底座文件设想是否一致。

重点确认：

1. 当前前台路由结构；
2. 当前离婚力量表首页入口；
3. 当前题库文件位置；
4. 当前计分逻辑文件；
5. 当前结果页组件结构；
6. 当前简版结果图导出实现；
7. 当前 Supabase 提交 payload 构建方式；
8. 当前后台列表页查询与筛选结构；
9. 当前后台详情页读取与展示结构；
10. 当前后台 CSV 导出实现；
11. 当前详细报告入口和 `/leads/[id]/report` 路由；
12. 当前是否已有 `assessment_type` 或 `result_payload` 字段使用痕迹。

### 4.2 只读检查输出要求

Codex 只读检查后应输出：

1. 当前相关文件清单；
2. 每个文件当前职责；
3. 建议新增文件路径；
4. 建议最小改动文件路径；
5. 是否发现与底座文件不一致的实际仓库情况；
6. 第一批开发建议；
7. 暂不修改代码。

### 4.3 只读检查后再决定批次

如果 Codex 只读检查发现：

- 某些文件路径与底座假设不同；
- 当前已有可复用多量表逻辑；
- 当前后台报告入口结构与预期不同；
- 当前数据库字段已有变化；

则应先调整开发路径，再进入编码。

## 5. 建议开发批次总览

第一阶段建议拆成 6 批开发。

| 批次 | 名称 | 目标 | 是否建议 git 收口 |
|---|---|---|---|
| 第 0 批 | 只读检查与数据库字段确认 | 确认仓库与 Supabase 当前状态 | 否 |
| 第 1 批 | 新量表前台题库与计分底座 | 新增题库、计分、结果文案配置 | 是 |
| 第 2 批 | 新量表前台页面与结果页 | 完成 `/narcissism-risk` 作答、结果、雷达图 | 是 |
| 第 3 批 | 简版结果图与留资写库 | PNG 导出、联系方式提交、Supabase 写入 | 是 |
| 第 4 批 | 后台列表与 CSV 适配 | 量表类型展示、筛选、高风险字段、CSV | 是 |
| 第 5 批 | 后台详情与旧报告隔离 | 新量表详情分流、原始答案展示、禁用旧报告 | 是 |
| 第 6 批 | 全链路回归与部署前收口 | 全量验收、README/底座同步建议、最终收口 | 是 |

说明：

- 第 0 批不改代码；
- 第 1 批可只新增配置与纯函数；
- 第 2 批先让前台本地跑通，不急于写库；
- 第 3 批再接 Supabase 写入，降低排查难度；
- 第 4、5 批再处理后台，避免前后台同时出问题；
- 每批完成验收后建议 git 收口，便于回滚。

## 14. 风险点与回避策略

### 14.1 风险：误改离婚力量表主链路

回避策略：

- 新增独立路由；
- 新增独立题库；
- 新增独立计分文件；
- 每批回归旧量表；
- 不大规模重构 `app/page.js`。

### 14.2 风险：结果等级含义混淆

回避策略：

- 后台显示必须结合 `assessment_type`；
- 新量表 `high` 只显示为“高风险”；
- 不复用离婚力量表准备度颜色和文案；
- CSV 增加量表类型列。

### 14.3 风险：高风险触发题被总分稀释

回避策略：

- 独立计算 `high_risk_triggered`；
- 独立保存 `high_risk_items`；
- 结果页和后台单独展示；
- 不用总等级覆盖高风险提示。

### 14.4 风险：随机题序导致答案无法还原

回避策略：

- 答案按 `question_id` 存储；
- `question_order` 保存完整 40 题；
- 后台根据题库配置还原题干和维度。

### 14.5 风险：新量表误进入旧详细报告

回避策略：

- 详情页隐藏旧报告入口；
- report 路由判断 `assessment_type`；
- 新量表记录显示第二阶段占位提示；
- 回归旧报告功能。

### 14.6 风险：数据库字段缺失导致写库失败

回避策略：

- 第 0 批确认字段；
- 第 3 批前确认 Supabase 字段已新增；
- 首次写库用测试记录；
- 错误提示可见。

### 14.7 风险：前台文案诊断化或恐吓式营销

回避策略：

- 使用底座文档中的结果页文案；
- 禁用“诊断 NPD”“对方一定危险”等表达；
- 高风险提示强调现实支持和专业帮助，不制造恐慌。

## 19. 阶段性结论

本文件确认了“配偶高自恋特质与高冲突婚姻风险自测量表”第一阶段开发的推荐路径：

1. 先做只读检查；
2. 再做题库与计分底座；
3. 再做前台页面和结果页；
4. 再接简版结果图与写库；

6. 再适配后台详情并隔离旧报告；
7. 最后做全链路回归与 git 收口。

该路径的核心目的是：

**以最小风险把第二套量表接入现有系统，同时保护离婚力量表已经完成的稳定前台、后台和详细报告能力。**

第一阶段完成后，项目将具备双量表入口与统一后台管理的基础能力；第二阶段再根据领导反馈和文案准备情况，推进新量表详细报告、A4 报告、移动端长图报告和 PDF 导出能力。
