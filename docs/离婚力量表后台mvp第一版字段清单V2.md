# 离婚力量表后台 MVP 第一版字段清单（阶段更新版｜第 6-A 双量表回归后）

## 1. 文档用途

本文件用于将《离婚力量表后台 MVP 范围与数据口径草案》进一步压实为可执行的字段清单，供以下环节统一使用：

- Supabase 表结构核对；
- 后台 MVP 页面字段取用；
- 后台列表页、详情页、报告页字段边界判断；
- Codex 最小改动方案评审；
- 后续字段说明与交接。

本文档为阶段更新版，重点补充以下当前事实：

1. 主表仍为 `assessment_results`；
2. 后台 MVP 已从单一离婚力量表后台扩展为两套量表共用后台；
3. 新量表通过 `assessment_type`、`result_payload`、`service_intent` 接入现有主表；
4. 第一阶段仍以扩展现有主表为主，不拆出复杂多表；
5. 后台 MVP 第一版目标仍是“能看、能筛、能改、能导”；
6. `result_level` 必须结合 `assessment_type` 解读，后台筛选已按量表类型区分；
7. `service_type` 已更新为当前 9 项后台服务类型选项，且不同于前台 `service_intent`；
8. 列表页已支持手动勾选记录后批量硬删除，但不新增删除字段、不做软删除或回收站；
9. 两套量表单条详细报告页均已完成，并支持 A4 网页端报告、移动端长图报告、PNG 导出与 PDF 导出；
10. 当前尚未做 `report_content` 持久化、报告审核定稿、报告文件存储、用户端授权查看、多账号、复杂角色权限、操作日志与保存冲突检测。

## 2. 字段清单使用原则

### 2.1 字段分层

当前字段统一按五层理解：

1. 前台测评结果字段；
2. 用户留资字段；
3. 后台跟进字段；
4. 建联补充信息字段；
5. 报告与扩展预留字段。

### 2.2 字段命名原则

- 数据库字段统一使用英文 snake_case；
- 枚举值统一使用英文稳定代码；
- 页面展示时再映射中文名称；
- 第一版尽量避免使用仅供展示的冗余字段；
- 当前报告导出功能不应为“导出动作本身”新增字段，除非未来进入报告持久化 / 导出日志专项。

### 2.3 当前默认主表

第一版后台 MVP 默认仍以：

**`assessment_results`**

作为线索主表。

原因：

- 前台提交链路已经稳定写入该表；
- 测评结果、联系方式、跟进字段和报告所需数据当前均能从该表及现有配置中取得；
- 对 MVP 来说，继续使用单主表最符合最小改动原则；
- 当前不需要为 PDF / PNG 导出新增报告表。

当前量表类型口径：

- `divorce_readiness`：离婚力量表；
- `spousal_narcissism_risk`：配偶高自恋特质与高冲突婚姻风险自测量表；
- 历史空值或旧 `divorce_scale`：按离婚力量表兼容处理。

## 3. 字段总表

以下为当前第一版建议字段清单。

字段属性说明：

- 字段类型：指建议在 Supabase / Postgres 中采用的字段类型；
- 来源：指主要由前台写入、后台维护，或系统自动生成；
- 前台写入：指是否在当前前台提交链路中写入；
- 后台可编辑：指是否应在后台 MVP 第一版允许人工编辑；
- 报告使用：指当前单条详细报告是否使用该字段或由该字段间接参与生成。

## 4. 前台测评结果字段

### 4.1 `id`

- 字段含义：主键 ID；
- 建议类型：`uuid`；
- 来源：数据库自动生成；
- 是否必填：是；
- 默认值：数据库默认生成；
- 前台写入：否；
- 后台可编辑：否；
- 报告使用：是，用于识别单条记录、生成报告路由与必要时生成导出文件名；
- 备注：主记录唯一标识。

### 4.2 `created_at`

- 字段含义：记录创建时间；
- 建议类型：`timestamptz`；
- 来源：数据库自动生成；
- 是否必填：是；
- 默认值：`now()`；
- 前台写入：否或可省略；
- 后台可编辑：否；
- 报告使用：是，可作为报告生成或提交时间展示依据之一；
- 备注：用于列表排序、筛选、导出与报告基础信息展示。

### 4.2A `assessment_type`

- 字段含义：量表类型代码；
- 建议类型：`text`；
- 来源：前台提交；
- 是否必填：建议新记录必填；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是，用于决定详情页、结果摘要和详细报告模板；
- 当前值：
  - `divorce_readiness`：离婚力量表；
  - `spousal_narcissism_risk`：配偶高自恋风险量表；
  - 历史空值或旧 `divorce_scale`：按离婚力量表兼容处理。
- 备注：后台列表筛选、结果等级筛选和报告入口都应优先依据该字段识别量表类型。

### 4.2B `result_payload`

- 字段含义：结构化结果扩展数据；
- 建议类型：`jsonb`；
- 来源：前台计分结果；
- 是否必填：新量表记录建议写入，离婚力量表历史记录不强制要求；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是，主要用于新量表详情页、摘要和详细报告；
- 当前新量表主要结构：
  - `average_score`；
  - `valid_answer_count`；
  - `na_answer_count`；
  - `dimension_validity`；
  - `dimension_details`；
  - `high_risk_triggered`；
  - `high_risk_items`；
  - `primary_risk_dimensions`；
  - `question_order`。
- 备注：不要要求离婚力量表历史记录必须补齐该字段。

### 4.2C `service_intent`

- 字段含义：前台三分流服务意向；
- 建议类型：`text`；
- 来源：前台留资分流；
- 是否必填：建议新记录写入；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：通常不进入报告正文，可用于后台列表、详情页和 CSV；
- 当前值：
  - `legal_support`：需要法律支持；
  - `psychological_support`：需要心理支持；
  - `deep_report`：仅需深度报告。
- 备注：该字段不同于后台人工维护的 `service_type`，不要混用。

### 4.3 `total_score`

- 字段含义：有效题目实际总分；
- 建议类型：`integer`；
- 来源：前台计分结果；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是；
- 备注：结果核心字段，不应由后台人工修改。

### 4.4 `dynamic_full_score`

- 字段含义：按有效题目动态计算的满分；
- 建议类型：`integer`；
- 来源：前台计分结果；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是；
- 备注：用于得分率换算与报告关键指标展示。

### 4.5 `score_rate`

- 字段含义：得分率；
- 建议类型：`numeric(5,2)`；
- 来源：前台计分结果；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是；
- 备注：建议存数值，不存百分号文本。

### 4.6 `result_level`

- 字段含义：结果等级代码，必须结合 `assessment_type` 解读；
- 建议类型：`text`；
- 来源：前台结果判断；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是；
- 离婚力量表口径：
  - `high`：准备充分；
  - `medium` 或 `mid`：准备一般；
  - `low`：准备不足。
- 配偶高自恋风险量表口径：
  - `low`：低风险；
  - `mild`：轻度风险；
  - `moderate`：中度风险；
  - `high`：高风险。
- 备注：后台列表结果等级筛选必须按 `assessment_type` 区分，避免跨量表语义串台。

### 4.7 `result_label`

- 字段含义：结果等级中文标签；
- 建议类型：`text`；
- 来源：前台结果判断；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是；
- 建议值示例：
  - `从容通关者`；
  - `稳健备战者`；
  - `急速蓄力者`。
- 备注：用于后台快速查看、CSV 导出与报告展示。

### 4.8 `child_gate_answer`

- 字段含义：是否进入子女维度的系统分流结果；
- 建议类型：`boolean`；
- 来源：前台系统分流题；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：间接使用；
- 建议值：
  - `true`：进入 D3；
  - `false`：跳过 D3。
- 备注：用于结果展示、后台筛选与报告维度展示边界。

### 4.9 `cross_border_gate_answer`

- 字段含义：是否进入跨境维度的系统分流结果；
- 建议类型：`boolean`；
- 来源：前台系统分流题；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：间接使用；
- 建议值：
  - `true`：进入 D7；
  - `false`：跳过 D7。
- 备注：用于结果展示、后台筛选与报告维度展示边界。

### 4.10 `weaknesses`

- 字段含义：当前短板维度列表；
- 建议类型：`text[]`；
- 来源：前台结果计算；
- 是否必填：否；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：可间接使用；
- 建议值示例：
  - `['D2']`；
  - `['D4','D5']`。
- 备注：建议存维度代码，不直接存长文案。

### 4.11 `dimension_scores`

- 字段含义：各维度平均分明细；
- 建议类型：`jsonb`；
- 来源：前台结果计算；
- 是否必填：建议是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：是，详细报告与雷达图核心依赖字段之一；
- 建议结构示例：

```json
{
  "D1": 3.67,
  "D2": 2.83,
  "D4": 3.2,
  "D5": 2.6,
  "D6": 3.0
}
```

- 备注：当前新提交记录已正式写入该字段；历史记录可能为空，后台详情页与报告页应继续支持 fallback 补算展示。

### 4.12 `answers`

- 字段含义：原始作答结果；
- 建议类型：`jsonb`；
- 来源：前台答题提交；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：间接使用，历史记录 fallback 补算和问题追溯可能依赖；
- 备注：用于详情页查看、后续报告生成与问题追溯。

### 4.13 `submission_source`

- 字段含义：提交来源；
- 建议类型：`text`；
- 来源：前台写入；
- 是否必填：是；
- 前台写入：是；
- 后台可编辑：否；
- 报告使用：一般不进入报告正文，可用于后台基础信息；
- 建议值示例：
  - `github_pages`；
  - `edgeone`；
  - `gpstrt`；
  - `zunerguangsh_sandra`；
  - `manual_test`。
- 备注：后续挂正式站后会变得更重要，建议提前规范。

## 7. 建联补充信息字段

- 前台测评；
- 计分；
- 结果等级判断；

- 来源：后台人工维护；
- 是否必填：否；
- 前台写入：否；
- 后台可编辑：是；
- 报告使用：否；
- 备注：仅作内部画像参考。

### 7.2 `client_gender`

- 字段含义：客户性别；
- 建议类型：`text`；
- 来源：后台人工维护；
- 是否必填：否；
- 前台写入：否；
- 后台可编辑：是；
- 报告使用：否；
- 备注：仅作内部识别和沟通辅助。

### 7.3 `client_location`

- 字段含义：客户所在地或主要办案关联地；
- 建议类型：`text`；
- 来源：后台人工维护；
- 是否必填：否；

### 7.4 `asset_tier_level`

## 8. 报告与扩展预留字段

当前两套量表的单条详细报告、A4 网页端预览、移动端长图预览、PNG 导出和 PDF 导出均已完成，但仍属于前端即时生成，不代表报告已持久化、审核或归档。

因此，本节字段仍属于“报告与扩展预留字段”，而不是完整报告系统字段。

### 8.1 `report_visibility`

- 字段含义：详细报告当前可见性；
- 建议类型：`text`；
- 来源：后台维护；
- 是否必填：是；
- 默认值：`internal_only`；
- 前台写入：否；
- 后台可编辑：是；
- 报告使用：间接相关；
- 建议值：
  - `hidden`；
  - `internal_only`；
  - `user_visible`。
- 当前口径：当前第一版默认仅内部可见，即使已支持 PDF 导出，也不代表用户端可见。

### 8.2 `report_version`

- 字段含义：当前对应的详细报告版本号；
- 建议类型：`text`；
- 来源：后台维护 / 系统生成；
- 是否必填：否；
- 前台写入：否；
- 后台可编辑：是；
- 报告使用：可作为模板版本提示；
- 建议值示例：
  - `v1`；
  - `v1.1`；
  - `internal_rule_v1`；
  - `a4_pdf_v1`。
- 当前口径：该字段可作为两套量表报告预览生成状态或模板版本提示，但尚不等于报告内容快照版本，也不等于律师定稿版本。

### 8.3 `report_generated_at`

- 字段含义：详细报告最近一次生成时间；
- 建议类型：`timestamptz`；
- 来源：系统生成；
- 是否必填：否；
- 前台写入：否；
- 后台可编辑：否；
- 报告使用：当前尚未严格启用；
- 当前口径：两套量表报告均为实时页面生成 + 前端导出，尚未建立严格的报告生成记录。后续如做报告持久化或导出日志，可正式启用。

## 9. 当前不新增的报告相关字段

尽管当前已经实现 PDF 导出，但本阶段不建议新增以下字段：

### 9.1 暂不新增 `report_content`

原因：

- 当前报告内容仍由页面实时生成；
- 当前不做报告内容快照；
- 当前不做律师审核定稿；
- 当前不开放用户端查看；
- 当前没有报告版本比对需求。

### 9.2 暂不新增 `report_pdf_url` / `report_png_url`

原因：

- 当前 PDF / PNG 文件由浏览器前端即时下载；
- 系统不保存 PDF / PNG 文件；
- 没有云存储或文件归档链路；
- 暂无用户端下载历史需求。

### 9.3 暂不新增 `report_exported_at`

原因：

- 当前未记录每次导出行为；
- 导出仍是内部即时动作；
- 若未来需要审计，应单独设计导出日志表，而不是简单加单个时间字段。

### 9.4 暂不新增 `report_review_status`

原因：

- 当前没有律师审核流程；
- 当前报告不作为定稿法律意见；
- 若未来需要审核，应与报告内容快照和版本化一起设计。

### 9.5 暂不新增 `report_file_storage_key`

原因：

- 当前没有文件存储系统；
- PDF / PNG 不上传至 Supabase Storage 或其他对象存储；
- 不应提前引入无实际使用的存储字段。

### 9.6 暂不新增批量删除相关字段

当前后台列表页已支持手动勾选记录后删除所选记录，但该能力是后台操作行为，不是字段能力。

本阶段不新增：

- `deleted_at`；
- `deleted_by`；
- `delete_reason`；
- soft delete 状态字段；
- 回收站相关字段。

当前删除口径为硬删除，不做软删除，不做回收站，也不支持“删除当前筛选全部结果”。

## 10. 字段使用边界总结

### 10.1 前台只写入测评与留资字段

前台应继续只负责：

- 测评结果；
- 分流结果；
- 量表类型；
- 结构化结果扩展数据；
- 前台服务意向；
- 维度分数；
- 原始答案；
- 联系方式；
- 提交来源。

前台不应写入：

- 后台跟进字段；
- 建联补充字段；
- 报告审核字段；
- 报告归档字段；
- 内部人员字段。

### 10.2 后台可编辑字段需控制在管理与建联信息

后台第一版可编辑：

- 跟进状态；
- 服务类型；
- 负责人；
- 约面信息；
- 内部备注；
- 建联补充信息；
- 报告可见性 / 版本等预留字段。

后台不应编辑：

- 原始答案；
- 总分；
- 动态满分；
- 得分率；
- 量表类型；
- 前台服务意向；
- 结构化结果扩展数据；
- 维度分数；
- 结果等级；
- 系统分流结果。

### 10.3 报告页只读取，不改写核心测评字段

当前报告页应只读取：

- 测评结果字段；
- 维度分数字段；
- 联系人称呼；
- 报告文案配置；
- 必要的报告预留字段。

当前报告页不应：

- 改写数据库；
- 保存报告内容；
- 写入 PDF 文件 URL；
- 写入导出日志；
- 改变用户可见性；
- 改变跟进状态。

### 10.4 PDF / PNG 导出不等于报告定稿

当前导出动作不应被理解为：

- 报告已审核；
- 报告已归档；
- 报告已锁定；
- 用户已可查看；
- 律师已出具正式意见。

## 12. 当前一句话结论

当前后台 MVP 第一版字段体系仍以 `assessment_results` 为线索主表，已经支撑两套量表的列表、筛选、详情、跟进、建联补充、CSV 导出、批量勾选硬删除、单条详细报告、PNG 导出与 PDF 导出的完整阶段性闭环；但报告导出仍是前端即时生成能力，不新增报告持久化字段，不保存文件，不开放用户端，不做审核定稿。后续如需多人协作、操作日志、软删除 / 回收站、报告归档或用户授权查看，应另行进入专项数据结构设计。
