# 配偶高自恋特质量表题目-维度-计分映射表 V1

## 1. 文档用途

本文档用于将《配偶高自恋特质与高冲突婚姻风险自测量表》转化为网页端可配置题库，作为前端展示、题目随机、必答校验、反向计分、高风险触发识别、维度均分计算、结果页输出、Supabase 写入与后台详情展示的直接配置依据。

本文档是开发前的题库与计分映射底座文件，不是结果页文案主档，也不是后台数据库方案。

本文档主要解决以下问题：

1. 40 道题如何统一编号；
2. 每道题归属于哪个维度；
3. 每道题是否反向计分；
4. 每道题是否属于高风险触发题；
5. 每道题是否必答；
6. 每道题是否允许“不适用”；
7. 每道题是否纳入总分和维度均分；
8. 前端随机题序和按 `question_id` 存答案时应遵循何种数据口径。

---

## 2. 总体规则

### 2.1 量表结构

本量表共 40 题，设置 5 个一级维度，每个维度 8 题。

五个维度为：

| 维度编码 | 维度名称 | 题目数 |
|---|---|---:|
| N1 | 自我重要感与特权感 | 8 |
| N2 | 赞赏依赖与羞耻暴怒 | 8 |
| N3 | 共情缺损与责任外归因 | 8 |
| N4 | 操控剥削与第三方动员 | 8 |
| N5 | 高冲突升级与安全风险 | 8 |

题目总数：40 题。

### 2.2 作答规则

本量表所有正式题均为必答题。

本量表不设置：

- “与本人情况无关”；
- “不适用”；
- 子女分流题；
- 跨境分流题；
- 整维跳过逻辑。

用户必须完成全部 40 题后，才可提交并查看结果。

### 2.3 展示顺序规则

本量表网页端应随机展示题目顺序。

随机展示规则：

1. 前端每次进入测评时生成一组随机题序；
2. 用户在本次测评中按该随机顺序完成作答；
3. 题目展示顺序不改变题目本身的 `question_id`；
4. 答案必须按 `question_id` 存储，不得按展示顺序存储；
5. 提交时必须保存本次实际展示题序 `question_order`；
6. 后台详情页和后续报告可根据 `question_id` 还原题目、维度与作答。

### 2.4 计分方向

本量表的分数方向为：

**分数越高，代表高自恋互动特征或高冲突婚姻风险越明显。**

注意：该方向与离婚力量表不同。离婚力量表高分代表准备更充分；本量表高分代表风险更高。

## 3. 字段定义

本映射表建议在前端题库配置中至少保留以下字段。

| 字段名 | 含义 |
|---|---|
| `question_id` | 题目唯一编号 |
| `dimension_code` | 维度编码 |
| `dimension_name` | 维度名称 |
| `question_no` | 题目在原始审核稿中的顺序号 |
| `question_text` | 题干 |
| `option_type` | 选项类型 |
| `reverse_scored` | 是否反向计分 |
| `high_risk_trigger` | 是否为高风险触发题 |
| `required` | 是否必答 |
| `allow_not_applicable` | 是否允许“不适用” |
| `included_in_total` | 是否纳入总分 |
| `included_in_dimension_avg` | 是否纳入维度均分 |
| `measurement_focus` | 测量重点 |
| `notes` | 备注 |

### 3.1 字段口径说明

本量表所有题统一采用：

- `option_type = likert_5`
- `required = true`
- `allow_not_applicable = false`
- `included_in_total = true`
- `included_in_dimension_avg = true`

其中：

- `reverse_scored = true` 仅适用于第 7、13、22、32、40 题；
- `high_risk_trigger = true` 仅适用于第 34、35、36、37 题；
- `measurement_focus` 用于后台详情、开发理解和后续报告文案承接，前台答题页通常不直接展示。

## 4. 选项配置标准

### 4.1 标准 5 分选项

| 选项文案 | 原始分值 |
|---|---:|
| 完全不符合 | 1 |
| 不太符合 | 2 |
| 一般符合 | 3 |
| 基本符合 | 4 |
| 完全符合 | 5 |

### 4.2 反向计分规则

反向计分题的原始选择与实际计分相反。

| 原选项 | 原始分值 | 反向题实际计分 |
|---|---:|---:|
| 完全不符合 | 1 | 5 |
| 不太符合 | 2 | 4 |
| 一般符合 | 3 | 3 |
| 基本符合 | 4 | 2 |
| 完全符合 | 5 | 1 |

### 4.3 反向计分题清单

本量表反向计分题共 5 题：

| 题号 | question_id | 所属维度 |
|---:|---|---|
| 7 | N1_Q07 | N1 自我重要感与特权感 |
| 13 | N2_Q13 | N2 赞赏依赖与羞耻暴怒 |
| 22 | N3_Q22 | N3 共情缺损与责任外归因 |
| 32 | N4_Q32 | N4 操控剥削与第三方动员 |
| 40 | N5_Q40 | N5 高冲突升级与安全风险 |

### 4.4 高风险触发题清单

本量表高风险触发题共 4 题：

| 题号 | question_id | 所属维度 | 触发条件 |
|---:|---|---|---|
| 34 | N5_Q34 | N5 高冲突升级与安全风险 | 原始分值 ≥ 4 |
| 35 | N5_Q35 | N5 高冲突升级与安全风险 | 原始分值 ≥ 4 |
| 36 | N5_Q36 | N5 高冲突升级与安全风险 | 原始分值 ≥ 4 |
| 37 | N5_Q37 | N5 高冲突升级与安全风险 | 原始分值 ≥ 4 |

说明：

- 高风险触发题不做反向计分；
- 触发判断使用用户原始选择分值；
- 任一高风险触发题原始分值为 4 或 5，即 `high_risk_triggered = true`；
- 所有触发题的 `question_id` 应写入 `result_payload.high_risk_items`。

## 5. 维度编码与题号规则

### 5.1 维度编码

| 维度编码 | 维度名称 | 建议前台短名 |
|---|---|---|
| N1 | 自我重要感与特权感 | 特权 |
| N2 | 赞赏依赖与羞耻暴怒 | 暴怒 |
| N3 | 共情缺损与责任外归因 | 共情 |
| N4 | 操控剥削与第三方动员 | 操控 |
| N5 | 高冲突升级与安全风险 | 升级 |

前台短名仅供雷达图和空间有限的展示场景使用，正式结果页解释应使用完整维度名称。

### 5.2 question_id 规则

建议采用以下编号规则：

`N{维度序号}_Q{两位原始题号}`

示例：

- 第 1 题：`N1_Q01`
- 第 7 题：`N1_Q07`
- 第 13 题：`N2_Q13`
- 第 34 题：`N5_Q34`

说明：

- `question_id` 必须稳定，不应因前端随机展示顺序变化而变化；
- `question_no` 保留原始审核稿题号；
- `question_id` 用于答案存储、后台还原、报告生成与问题追踪。

## 7. 计分计算口径

### 7.1 单题实际得分

每题最终进入计算的分值称为“实际得分”。

- 普通题：实际得分 = 原始分值；
- 反向题：实际得分 = 6 - 原始分值。

### 7.2 总分

总分计算方式：

`total_score = 40 题实际得分之和`

取值范围：

- 最低：40；
- 最高：200。

### 7.3 动态满分

本量表无跳题、无不适用选项，因此动态满分固定为：

`dynamic_full_score = 200`

### 7.4 总平均分

总平均分计算方式：

`average_score = total_score / 40`

总平均分是本量表结果解释的主要口径。

建议页面展示保留 2 位小数。

### 7.5 得分率

得分率计算方式：

`score_rate = total_score / 200 * 100`

说明：

- 得分率主要用于兼容后台既有字段；
- 新量表结果页不应以得分率作为主要解释口径；
- 新量表结果页应优先展示总平均分、风险等级、五维均分和高风险触发状态。

### 7.6 维度平均分

每个维度各 8 题。

维度平均分计算方式：

`dimension_average = 该维度 8 题实际得分之和 / 8`

建议 `dimension_scores` 存储结构如下：

```json
{
  "N1": 3.25,
  "N2": 3.75,
  "N3": 2.88,
  "N4": 4.13,
  "N5": 3.50
}
```

### 7.7 主要风险维度

第一阶段建议按维度平均分从高到低识别主要风险维度。

建议规则：

1. 将 N1–N5 按维度平均分降序排列；
2. 默认取最高的 1–2 个维度作为 `primary_risk_dimensions`；
3. 若存在并列，按 N1 → N2 → N3 → N4 → N5 的顺序稳定排序；
4. 若所有维度均处于较低分区，仍可展示最高维度，但文案应避免过度风险化。

建议写入：

```json
{
  "primary_risk_dimensions": ["N5", "N4"]
}
```

具体展示规则可在《配偶高自恋特质量表结果分级规则与结果页文案框架 V1》中进一步细化。

## 8. 风险等级映射

本量表按总平均分划分四档风险。

| 总平均分区间 | result_level | result_label |
|---|---|---|
| 1.00–1.80 | low | 低风险 |
| 1.81–2.60 | mild | 轻度风险 |
| 2.61–3.40 | moderate | 中度风险 |
| 3.41–5.00 | high | 高风险 |

说明：

- `result_level` 使用英文稳定代码；
- `result_label` 使用中文展示标签；
- 前台、后台、CSV 导出应统一使用上述四档；
- 新量表的 `high` 表示“高风险”，不得与离婚力量表中的正向高分含义混淆。

## 9. 答案存储建议

### 9.1 answers 存储原则

`answers` 应按 `question_id` 存储，而不是按随机展示序号存储。

建议结构示例：

```json
{
  "N1_Q01": {
    "raw_score": 4,
    "score": 4
  },
  "N1_Q07": {
    "raw_score": 4,
    "score": 2
  },
  "N5_Q34": {
    "raw_score": 5,
    "score": 5
  }
}
```

其中：

- `raw_score` 为用户原始选择分值；
- `score` 为完成反向计分后的实际得分；
- 普通题 `raw_score` 与 `score` 相同；
- 反向题 `raw_score` 与 `score` 不同。

### 9.2 question_order 存储原则

由于前端随机展示题序，提交时应在 `result_payload.question_order` 中保存完整展示顺序。

示例：

```json
{
  "question_order": [
    "N3_Q18",
    "N1_Q02",
    "N5_Q34",
    "N4_Q30"
  ]
}
```

实际开发时应保存完整 40 个 `question_id`。

### 9.3 高风险触发存储原则

建议在 `result_payload` 中保存：

```json
{
  "high_risk_triggered": true,
  "high_risk_items": ["N5_Q34", "N5_Q37"]
}
```

其中：

- `high_risk_triggered` 为布尔值；
- `high_risk_items` 为触发题目的 `question_id` 数组；
- 未触发时建议写入空数组，而不是省略字段。

未触发示例：

```json
{
  "high_risk_triggered": false,
  "high_risk_items": []
}
```

## 11. 开发注意事项

### 11.1 与离婚力量表的关键差异

开发时必须注意：

1. 本量表不允许“不适用”；
2. 本量表无分流题；
3. 本量表 40 题全部必答；
4. 本量表高分代表风险更高；
5. 本量表结果解释主口径为总平均分，不是得分率；
6. 本量表存在高风险触发题；
7. 本量表随机题序必须保存；
8. 本量表不能误用离婚力量表的“准备度”文案和结果颜色逻辑。

### 11.2 反向题注意事项

反向题应同时保留：

- 用户原始选择分值；
- 反向换算后的实际得分。

原因：

- 原始分值有助于后台查看用户选择；
- 实际得分用于计分和结果判断；
- 后续报告若需要解释具体题目，应能区分原始选择和计分结果。

### 11.3 高风险题注意事项

高风险触发判断应基于原始分值，而不是维度平均分。

例如：

- 即便总平均分不是高风险；
- 只要 N5_Q34、N5_Q35、N5_Q36、N5_Q37 任一题原始分值 ≥ 4；
- 仍应显示高风险触发提示。

### 11.4 后台显示注意事项

后台详情页展示原始答案时，应能标识：

- 题号；
- 题干；
- 所属维度；
- 用户原始选择；
- 原始分值；
- 实际计分；
- 是否反向题；
- 是否高风险触发题；
- 是否已触发高风险。

第一阶段不要求做复杂视觉报告，但后台基础详情必须可读。

## 12. 阶段性结论

本映射表确认了“配偶高自恋特质与高冲突婚姻风险自测量表”第一阶段网页端开发所需的题库、维度、计分与高风险触发基础口径。

本量表开发时应坚持以下底线：

1. `question_id` 稳定；
2. 题序可以随机，但答案必须按 `question_id` 存储；
3. 反向计分必须准确；
4. 高风险触发题必须单独识别；
5. 五维均分必须准确；
6. 总平均分是结果解释主口径；
7. 得分率仅作后台兼容字段；
8. 高分代表风险更高；
9. 所有题必答，无不适用；
10. 后续页面文案、后台适配和 Codex 开发均应以本表为题库与计分依据。
