# 配偶高自恋特质量表网页端产品与开发方案 V1

## 1. 文档用途

本文档用于在“配偶高自恋特质与高冲突婚姻风险自测量表”进入 VS Code + Codex 开发前，统一本量表网页端第一阶段的产品定位、功能范围、前后台边界、数据接入原则与开发约束。

本文档是新量表网页端开发的第一份总纲型底座文件，主要回答以下问题：

1. 新量表网页端应被定位为何种产品；
2. 第一阶段应完成哪些功能；
3. 第一阶段明确不做哪些功能；
4. 新量表如何复用现有“离婚力量表网页端”项目能力；
5. 新量表如何避免破坏现有离婚力量表前后台稳定基线；
6. 新量表与后台、数据库之间应如何低耦合接入；
7. 进入 Codex 开发前应保持哪些产品与技术边界。

本文档不是：

- 题目-维度-计分映射表；
- 结果页完整文案主档；
- 数据库 SQL 迁移脚本；
- Codex 开发 prompt；
- 后台详细报告方案；
- 第二阶段详细解读报告文案主档。

后续应在本文档基础上继续形成以下底座文件：

1. 《配偶高自恋特质量表题目-维度-计分映射表 V1》；
2. 《配偶高自恋特质量表结果分级规则与结果页文案框架 V1》；
3. 《配偶高自恋特质量表网页信息架构与页面文案草案 V1》；
4. 《配偶高自恋特质量表后台与数据库适配方案 V1》；
5. 《配偶高自恋特质量表开发路径与验收清单 V1》。

## 3. 新量表产品定位

### 3.1 产品名称

本量表正式名称暂定为：

**配偶高自恋特质与高冲突婚姻风险自测量表**

为便于内部开发命名，可使用稳定代码：

`spousal_narcissism_risk`

前台入口暂定为：

`/narcissism-risk`

### 3.2 产品核心定位

本量表定位为：

**面向婚姻冲突、离婚协商、财产分割、子女安排等场景的婚姻互动风险自测工具。**

它的核心功能不是判断配偶是否患有某种人格障碍，而是帮助用户初步识别：

- 关系中是否存在较高的自恋型互动特征；
- 婚姻冲突是否具有持续升级风险；
- 对方是否存在低共情、羞耻暴怒、操控剥削、第三方动员、威胁恐吓等高冲突风险信号；
- 用户是否需要优先考虑现实安全、证据保存、沟通边界与专业咨询。

### 3.3 业务定位

本量表在律所业务中的定位是：

1. 婚姻家事法律服务的前置风险识别工具；
2. 潜在客户自我梳理婚姻冲突结构的在线入口；
3. 律师咨询前的信息收集与风险预筛工具；
4. 公域内容、官网、社交媒体流量进入法律服务链路的互动承接工具。

### 3.4 与离婚力量表的区别

本量表与既有离婚力量表存在根本差异：

| 对比项 | 离婚力量表 | 配偶高自恋特质量表 |
|---|---|---|
| 核心评估对象 | 用户自身离婚准备能力 | 配偶或伴侣在关系中的高冲突风险表现 |
| 主要问题 | “我是否准备好离婚？” | “这段关系是否存在高自恋互动和高冲突风险？” |
| 得分方向 | 高分代表准备更充分 | 高分代表风险更高 |
| 结果基准 | 得分率、动态满分、准备度等级 | 总平均分、五维均分、风险等级、高风险触发题 |
| 不适用选项 | 存在子女/跨境等客观不适用场景 | 不设置“不适用”，40题全部必答 |
| 结果解释重点 | 准备度、短板、行动建议 | 风险识别、安全提示、沟通边界与咨询引导 |

因此，新量表不能直接复用离婚力量表的结果等级颜色、正向表述和“准备充分”解释逻辑。

### 3.5 合规与专业边界

本量表必须明确：

- 不用于判断对方是否患有 NPD / 自恋型人格障碍；
- 不构成临床诊断；
- 不构成心理治疗建议；
- 不构成正式法律意见；
- 不应鼓励用户给对方贴人格标签；
- 不应鼓励用户在无安全预案的情况下激化冲突；
- 若存在威胁、恐吓、暴力、限制行动、自伤他伤威胁等风险，应优先寻求现实支持、报警、申请保护措施或咨询专业人士。

页面文案应尽量使用：

- “高自恋互动特征”；
- “高冲突婚姻风险”；
- “风险信号”；
- “关系互动模式”；
- “安全风险提示”。

应避免使用：

- “对方就是 NPD”；
- “对方患有人格障碍”；
- “对方一定危险”；
- “本结果可以证明对方有病”；
- “凭本测评即可判断离婚策略”。

## 4. 第一阶段产品目标

### 4.1 阶段目标

第一阶段目标是形成一个可上线试用的第二量表 MVP：

1. 用户可通过 `/narcissism-risk` 进入新量表；
2. 用户可完成 40 题随机顺序作答；
3. 系统可完成反向计分、五维均分、总平均分、四档风险判断；
4. 系统可识别高风险触发题；
5. 用户可查看结果页、五维雷达图、高风险提示卡；
6. 用户可导出简版结果图 PNG；
7. 用户可在结果页提交联系方式；
8. 新量表结果可写入 Supabase；
9. 后台列表可识别并筛选新量表记录；
10. 后台详情页可查看新量表基础结果。

### 4.2 阶段原则

第一阶段遵循以下原则：

1. **低耦合新增。** 以新增文件和局部适配为主，避免改坏离婚力量表主链路。
2. **不做通用引擎重构。** 当前不把项目重构为完整多量表平台。
3. **结果解释克制。** 不做诊断化、标签化、恐吓式表达。
4. **数据结构稳妥扩展。** 继续使用现有 `assessment_results` 主表，通过 `assessment_type` 与 `result_payload` 承接新量表差异。
5. **后台只做基础适配。** 第一阶段不接入新量表后台详细报告。
6. **保留后续扩展空间。** 为第二阶段详细报告、后台报告导出、多量表统一化预留可能性。

## 5. 第一阶段功能范围

## 5.1 前台入口与答题流程

第一阶段前台新增独立入口：

`/narcissism-risk`

该入口应与既有离婚力量表首页相互独立，不改变现有 `app/page.js` 主入口。

答题流程应支持：

- 新量表首页 / 引导页；
- 测评说明；
- 40 题正式作答；
- 题目顺序随机；
- 进度展示；
- 全部必答校验；
- 提交后生成结果；
- 重新测评。

与离婚力量表不同，新量表不设置：

- 子女分流题；
- 跨境分流题；
- “与本人情况无关”选项；
- 动态跳过维度逻辑。

### 5.2 题目与选项范围

新量表共 40 题，分为 5 个维度，每维 8 题。

五个维度为：

1. N1 自我重要感与特权感；
2. N2 赞赏依赖与羞耻暴怒；
3. N3 共情缺损与责任外归因；
4. N4 操控剥削与第三方动员；
5. N5 高冲突升级与安全风险。

统一采用 5 点李克特选项：

| 选项 | 原始分值 |
|---|---:|
| 完全不符合 | 1 |
| 不太符合 | 2 |
| 一般符合 | 3 |
| 基本符合 | 4 |
| 完全符合 | 5 |

40 题全部必答，不提供“不适用”或“与本人情况无关”。

### 5.3 随机题序

第一阶段必须支持题目随机顺序。

随机题序要求：

1. 每次进入测评时生成一组展示顺序；
2. 用户在该次测评内按该顺序作答；
3. 结果提交时保存实际展示顺序；
4. 答案按 `question_id` 存储，而不是按展示序号存储；
5. 后台详情页应能根据 `question_id` 还原题目与答案。

建议在提交数据中保存：

```json
{
  "question_order": ["N3_Q18", "N1_Q02", "N5_Q34"]
}
```

实际开发时应保存完整 40 个 `question_id`。

## 6. 第一阶段计分与结果范围

### 6.1 基础计分

每题原始分值为 1–5 分。

总分范围：

- 最低 40 分；
- 最高 200 分。

动态满分固定为：

`200`

得分率计算方式为：

`score_rate = total_score / 200 * 100`

但需要注意：

**得分率仅用于兼容后台既有字段，不作为新量表结果解释的主要口径。**

新量表结果解释的主要口径应为：

- 总平均分；
- 五维平均分；
- 风险等级；
- 高风险触发状态；
- 主要风险维度。

### 6.2 反向计分

反向计分题包括：

- 第 7 题；
- 第 13 题；
- 第 22 题；
- 第 32 题；
- 第 40 题。

反向计分规则：

| 原始分值 | 实际计分 |
|---:|---:|
| 1 | 5 |
| 2 | 4 |
| 3 | 3 |
| 4 | 2 |
| 5 | 1 |

所有反向题必须先完成反向换算，再纳入总分、总平均分和维度平均分计算。

### 6.3 总平均分

总平均分计算方式：

`average_score = total_score / 40`

保留建议：

- 内部计算可保留更多小数；
- 页面展示建议保留 2 位小数；
- 后台详情页建议展示 2 位小数。

### 6.4 维度平均分

每个维度各 8 题。

维度平均分计算方式：

`dimension_average = 该维度实际计分总和 / 8`

维度分数建议以 `dimension_scores` 存储，例如：

```json
{
  "N1": 3.25,
  "N2": 3.75,
  "N3": 2.88,
  "N4": 4.13,
  "N5": 3.5
}
```

### 6.5 风险等级

新量表按总平均分分为四档：

| 总平均分区间 | 风险等级代码 | 展示标签 |
|---|---|---|
| 1.00–1.80 | low | 低风险 |
| 1.81–2.60 | mild | 轻度风险 |
| 2.61–3.40 | moderate | 中度风险 |
| 3.41–5.00 | high | 高风险 |

注意：

- 新量表高分代表风险更高；
- 不能沿用离婚力量表“高分更好”的颜色和鼓励语逻辑；
- `high` 在新量表中代表高风险，而不是准备充分；
- 后台展示时必须结合 `assessment_type` 判断含义。

### 6.6 高风险触发题

高风险触发题包括：

- 第 34 题；
- 第 35 题；
- 第 36 题；
- 第 37 题。

触发规则：

若任一高风险触发题选择：

- 基本符合；
- 完全符合；

即原始分值为 4 或 5，则：

`high_risk_triggered = true`

同时记录触发题目：

```json
{
  "high_risk_triggered": true,
  "high_risk_items": ["N5_Q34", "N5_Q37"]
}
```

高风险触发状态应影响：

- 前台结果页提示卡；
- 简版结果图提示；
- 后台列表标记；
- 后台详情页重点提示；
- CSV 导出字段。

高风险触发不必直接覆盖总平均分等级，但应在结果页中被明确提示。

## 7. 前台结果页范围

第一阶段新量表结果页应承担以下任务：

1. 让用户快速理解整体风险水平；
2. 展示五个维度的风险结构；
3. 标识主要风险维度；
4. 如触发高风险题，进行安全提示；
5. 引导用户保存结果、提交联系方式并考虑咨询专业人士；
6. 支持导出简版结果图。

### 7.1 结果总卡

结果总卡建议展示：

- 风险等级标签；
- 总平均分；
- 总分 / 满分；
- 简要解释；
- 风险方向提示：分数越高，代表相关风险信号越明显。

### 7.2 五维雷达图

结果页应展示五维雷达图。

可复用现有 `DimensionRadarChart.js`，但需要注意：

- 五维编码为 N1–N5；
- 雷达图含义为风险分布，不是能力准备度；
- 高分维度代表该风险主题更突出；
- 页面文案必须避免用户误解为“表现更好”。

建议雷达图维度短名：

| 维度代码 | 短名 |
|---|---|
| N1 | 特权 |
| N2 | 暴怒 |
| N3 | 共情 |
| N4 | 操控 |
| N5 | 升级 |

具体短名可在页面文案草案中进一步确认。

### 7.3 主要风险维度

结果页应基于五维均分识别主要风险维度。

建议第一阶段采用简单规则：

- 按维度平均分从高到低排序；
- 展示最高的 1–2 个维度作为主要风险维度；
- 若多个维度并列，可按 N1 → N5 的固定顺序展示。

后续结果分级文案文件中可进一步细化：

- 不同风险等级下展示几个维度；
- 高风险触发题是否优先覆盖维度提示；
- 是否设置“暂无明显突出维度”的兜底文案。

### 7.4 高风险触发提示卡

如 `high_risk_triggered = true`，结果页必须展示高风险提示卡。

提示卡表达应克制、清楚、以安全为先：

- 提醒用户该结果显示存在较强冲突升级或现实安全风险信号；
- 建议避免在无准备情况下激烈摊牌；
- 建议保存证据、减少单独正面冲突；
- 如涉及现实威胁、暴力、限制行动、自伤他伤威胁，应及时寻求现实支持、报警或咨询专业人士；
- 不得表述为“对方一定会伤害你”或“对方已经构成犯罪”。

如 `high_risk_triggered = false`，结果页可展示普通风险提示：

- 当前未触发最高优先级安全题；
- 但仍需结合总风险等级与维度结果判断关系风险；
- 若现实中出现威胁、暴力、跟踪、骚扰等情形，应优先以现实情况为准。

### 7.5 免责声明与边界提示

结果页必须保留边界提示：

- 本测评仅供婚姻互动风险识别与自我梳理参考；
- 不构成临床诊断；
- 不构成心理治疗建议；
- 不构成正式法律意见；
- 不应用于给对方贴标签或替代专业判断；
- 重大决策应结合具体情况咨询专业人士。

## 8. 留资与转化承接范围

### 8.1 留资字段

第一阶段新量表结果页应支持用户提交：

- 称呼 / 姓名：`contact_name`；
- 联系电话：`contact_phone`；
- 微信号：`contact_wechat`。

建议沿用离婚力量表当前留资模式：

- 称呼必填；
- 电话必填；
- 微信选填；
- 提交成功后按钮锁定，避免重复提交；
- 页面内展示 success / error 提示；
- 不跳转到独立留资页。

### 8.2 转化表达原则

新量表结果页的咨询引导应保持专业克制。

可以表达：

- 如果您正在经历长期否定、操控、威胁、骚扰或高冲突离婚协商，建议尽早咨询专业婚姻家事律师；
- 律师可帮助您梳理证据、评估沟通风险、制定财产与子女安排策略；
- 若存在现实安全风险，请优先保护自身和孩子安全。

不宜表达：

- “您必须马上离婚”；
- “对方已经是 NPD”；
- “不咨询律师就一定会出事”；
- “我们能保证解决高冲突婚姻问题”；
- “测评结果可作为直接胜诉依据”。

## 11. 数据写入原则

### 11.1 主表策略

第一阶段建议继续使用现有主表：

`assessment_results`

暂不新建独立主表。

原因：

1. 当前后台已经围绕 `assessment_results` 完成列表、详情、跟进字段和 CSV 导出；
2. 新量表第一阶段仍属于线索收集与基础结果查看，不需要独立业务表；
3. 共用主表有利于统一管理测评线索；
4. 可通过 `assessment_type` 区分不同量表；
5. 新量表特有结构可先放入 `result_payload`，避免主表膨胀。

### 11.2 建议新增 / 使用字段

第一阶段建议主表新增或使用：

- `assessment_type text`；
- `result_payload jsonb`。

其中：

`assessment_type` 用于区分量表类型。

建议取值：

- 离婚力量表：可补齐为 `divorce_readiness` 或保持历史为空并由后台兼容；
- 新量表：`spousal_narcissism_risk`。

`result_payload` 用于存储新量表特有结果结构。

### 11.3 新量表建议写入字段

新量表提交时建议写入：

- `assessment_type = "spousal_narcissism_risk"`；
- `total_score`：40题实际总分，范围 40–200；
- `dynamic_full_score = 200`；
- `score_rate = total_score / 200 * 100`；
- `result_level = low / mild / moderate / high`；
- `result_label = 低风险 / 轻度风险 / 中度风险 / 高风险`；
- `dimension_scores`：五维平均分；
- `answers`：原始答案，按 `question_id` 存储；
- `contact_name`；
- `contact_phone`；
- `contact_wechat`；
- `submission_source = "narcissism_risk_web"`；
- `follow_up_status = "new"`；
- `result_payload`。

### 11.4 `result_payload` 建议结构

建议结构如下：

```json
{
  "average_score": 3.42,
  "score_direction": "higher_is_riskier",
  "high_risk_triggered": true,
  "high_risk_items": ["N5_Q34", "N5_Q37"],
  "primary_risk_dimensions": ["N5", "N4"],
  "question_order": ["N3_Q18", "N1_Q02", "N5_Q34"]
}
```

实际开发时：

- `question_order` 应保存完整 40 题顺序；
- `high_risk_items` 应保存触发题目的 `question_id`；
- `primary_risk_dimensions` 应保存维度代码，而非长文案；
- 展示文案由前端或后台映射生成。

## 12. 后台第一阶段适配范围

第一阶段后台只做基础适配，不做新量表详细报告。

### 12.1 列表页适配

后台列表页应支持：

- 识别 `assessment_type`；
- 展示量表类型；
- 增加量表类型筛选；
- 对新量表记录展示风险等级；
- 展示高风险触发标记；
- CSV 导出补充量表类型和高风险字段。

列表页应避免混淆：

- 离婚力量表 `high` 代表准备较充分；
- 新量表 `high` 代表高风险。

因此列表页显示时应优先展示中文 `result_label`，并结合量表类型解释。

### 12.2 详情页适配

后台详情页应根据 `assessment_type` 分流展示。

新量表详情页第一阶段展示：

- 基础联系方式；
- 提交时间；
- 量表类型；
- 风险等级；
- 总平均分；
- 总分 / 满分；
- 五维均分；
- 高风险触发状态；
- 高风险触发题；
- 主要风险维度；
- 原始答案；
- 后台跟进字段；
- 内部备注；
- 建联补充信息。

### 12.3 详细报告入口处理

第一阶段新量表记录不应进入离婚力量表现有详细报告页。

若当前详情页对所有记录都有“查看详细报告”入口，则新量表记录应：

- 隐藏该入口；或
- 禁用该入口；或
- 显示提示：

“新量表详细报告将在第二阶段接入。”

不得让新量表记录误用离婚力量表的 A4 报告、移动端长图报告、PNG/PDF 深度报告导出逻辑。

## 14. 用户流程

第一阶段用户主流程为：

1. 用户从官网、文章、社交媒体或内部链接进入 `/narcissism-risk`；
2. 用户阅读量表说明与边界提示；
3. 用户点击开始测评；
4. 系统生成随机题目顺序；
5. 用户完成 40 题作答；
6. 系统校验全部必答；
7. 用户提交答案；
8. 前端完成计分与结果生成；
9. 用户查看风险等级、五维雷达图、主要风险维度和高风险提示；
10. 用户可导出简版结果图；
11. 用户填写联系方式并提交；
12. 结果与联系方式写入 Supabase；
13. 律所内部人员在后台查看并跟进。

---

## 15. 后台流程

第一阶段后台流程为：

1. 用户提交新量表结果；
2. Supabase `assessment_results` 生成新记录；
3. 后台列表页读取记录；
4. 列表页通过 `assessment_type` 识别为“配偶高自恋特质量表”；
5. 后台人员可按量表类型筛选；
6. 后台人员可查看风险等级和高风险触发标记；
7. 后台人员进入详情页；
8. 详情页展示新量表基础结果、五维均分和原始答案；
9. 后台人员维护跟进状态、服务类型、负责人、备注和建联补充信息；
10. 新量表详细报告入口暂不开放，等待第二阶段接入。

## 18. 阶段性结论

“配偶高自恋特质与高冲突婚姻风险自测量表”第一阶段开发，应被理解为：

**在现有离婚力量表网页端稳定基线上，低耦合新增第二套风险识别型量表入口，并通过 `assessment_type` 与 `result_payload` 接入同一后台管理系统。**

本阶段的核心不是建设完整多量表平台，也不是开发新量表深度报告系统，而是先完成：

- 前台可测；
- 结果可看；
- 图片可导；
- 留资可收；
- 数据可写；
- 后台可识别；
- 详情可查看；
- 原有系统不受影响。

只要第一阶段能够稳定实现上述闭环，即可为第二阶段详细报告、正式上线和多量表化演进奠定基础。
