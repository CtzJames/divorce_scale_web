### 2.8.1 修复一：删除 `proxy.js`，改为页面 / route / action 层鉴权

线上最初点击详情页 `/leads/[id]` 时出现：

`{"error":"Middleware execution failed","message":"t9.SharedCacheControls is not a constructor"}`

判断原因：

- `apps/admin-mvp/proxy.js` 的 matcher 覆盖 `/leads/:path*`；
- EdgeOne Pages 对 Next.js proxy / middleware + 动态详情路由存在兼容问题；
- 列表页、登录、Supabase 基础读写均正常，问题集中在 proxy / middleware 执行层。

修复方式：

- 删除 `apps/admin-mvp/proxy.js`；
- 保留页面级鉴权、Route Handler 鉴权和 Server Action 鉴权；
- 在以下页面增加 `export const dynamic = "force-dynamic"`：
  - `apps/admin-mvp/app/leads/page.js`；
  - `apps/admin-mvp/app/leads/[id]/page.js`；
  - `apps/admin-mvp/app/leads/[id]/report/page.js`。

### 2.8.2 修复二：退出登录跳转改为相对路径

线上点击“退出登录”后曾跳转至：

`https://localhost:9000/login`

判断原因：

- `apps/admin-mvp/app/api/auth/logout/route.js` 中使用 `NextResponse.redirect(new URL("/login", request.url))`；
- 在 EdgeOne Pages 上，`request.url` 可能是平台内部运行时地址，而不是用户真实访问域名；
- 因此 `/login` 被拼成了 `https://localhost:9000/login`。

修复方式：

- 将退出登录跳转改为相对路径 `Location: "/login"`；
- 不再依赖 `request.url` 的 origin；
- 后续即使绑定自定义域名，也会跳回当前站点的 `/login`。

### 2.8.3 修复三：允许 EdgeOne 公开域名执行 Server Actions

密钥轮换与环境变量更新后，在 EdgeOne 线上详情页修改跟进状态并保存时，曾出现：

`This page couldn’t load`

EdgeOne Cloud Functions 日志显示：

`x-forwarded-host header with value pages-pro-3-f4b9.pages-scf-hk-pro.qcloudteo.com does not match origin header with value divorce-scale-admin-mvp.edgeone.dev from a forwarded Server Actions request. Aborting the action.`

`Error: Invalid Server Actions request.`

判断原因：

- 打开 `/leads` 与 `/leads/[id]` 属于 GET 页面请求，可以正常打开；
- 点击“保存当前编辑”触发 Next.js Server Actions；
- Next.js Server Actions 会校验 `origin` 与 `host` / `x-forwarded-host`；
- EdgeOne 反向代理 / 云函数运行环境导致 `origin` 为公开域名 `divorce-scale-admin-mvp.edgeone.dev`，但 `x-forwarded-host` 为平台内部域名；
- Next.js 拒绝执行该 Server Action，导致保存动作 500。

修复方式：

- 在 `apps/admin-mvp/next.config.mjs` 中保留原有 `turbopack.root`；
- 新增 `experimental.serverActions.allowedOrigins`；
- 将当前 EdgeOne 公开域名加入允许列表：

```js
experimental: {
  serverActions: {
    allowedOrigins: [
      "divorce-scale-admin-mvp.edgeone.dev",
    ],
  },
},
```

当前验证结果：

- EdgeOne 重新部署后，后台详情页可正常修改用户状态并保存；
- 删除旧 Supabase key 后，后台仍可正常打开、操作与保存；
- 该问题已完成线上回归验收。

当前判断：

- EdgeOne Pages 海外可用区部署已完成技术验证；
- 它可以作为开发者线上验收环境；
- 但由于该部署选择“全球可用区（不含中国大陆）”，中国大陆访问仍不稳定，大部分领导与同事可能需要 VPN 才能访问；
- 因此当前 EdgeOne 海外部署不适合作为正式内部试用入口，也不适合作为正式上线方案。

- `3.0 <= score < 4.0`：琥珀金棕 / 中等；
- `4.0 <= score < 4.5`：绿色 / 较高；

总结果得分率颜色规则：

- `< 60%`：红色；

- `80% <= scoreRate < 90%`：绿色；
- `scoreRate >= 90%`：蓝色。

### 2.10.8 PDF 导出能力

后台单条详细报告已实现真正前端 PDF 文件导出。

技术路线：

- 使用 `html-to-image` 将 A4 页转为 PNG；
- 使用 `jspdf` 生成 PDF 文件；
- 按 `.a4-report-page` 逐页读取 A4 报告页；
- 每个 A4 页面转为一张图片后写入 PDF 对应页；
- 使用 `new jsPDF("p", "mm", "a4")`；
- 图片按 A4 页面尺寸写入 PDF；
- 直接下载 `.pdf` 文件；
- 不使用浏览器原生打印；
- 不弹出浏览器打印面板；
- 不依赖用户手动选择“保存为 PDF”。

为保证移动端预览状态下也能导出 A4 PDF，当前实现采用：

- A4 报告在移动端预览状态下仍以离屏方式真实挂载；
- 离屏挂载不使用 `display: none`、`visibility: hidden` 或 `opacity: 0`；
- PDF 导出仍可读取 A4 页节点；
- 移动端 PNG 导出继续使用 `mobileReportRef`，不受离屏 A4 报告影响。

当前新增依赖：

- `jspdf`

当前已完成本地与 EdgeOne 线上验收：

- 移动端长图预览正常；
- 网页端 PNG 导出正常；
- 移动端 PNG 导出正常；
- 网页端预览状态下 PDF 导出正常；

## 7. 当前正式部署方向

正式上线必须同时满足：

- 中国大陆用户可稳定访问前台；
- 中国大陆境内律所工作人员可稳定访问后台；

- 后台支持 Next.js 服务端能力、Cookie、Server Actions、动态路由与报告导出相关前端能力；
- 前台与后台分离部署，互不干扰。

当前推荐方向：

### 方案一：已备案域名子域名 + EdgeOne Pages 中国大陆 / 全球含大陆可用区

推荐作为正式上线首选方案。

适用条件：

- 域名已备案；
- 腾讯云账号实名认证与接入备案问题可解决；
- EdgeOne 中国大陆 / 全球含大陆区可完整支持当前后台 Next.js SSR、Route Handler、Server Actions 与报告导出能力；
- 静态资源、Logo、水印、PNG 导出、PDF 导出在正式域名下均能正常回归。

### 方案二：已备案域名子域名 + 中国大陆云服务器部署

推荐作为正式上线备选方案。

适用条件：

- EdgeOne 中国大陆区无法稳定承载后台；
- 律所或技术同事具备服务器运维能力；
- 可部署 Node.js / Next.js 服务端；
- 可配置 HTTPS、环境变量、进程管理、日志与备份。

### 不推荐正式上线方案

不推荐：

- EdgeOne Pages 全球可用区（不含中国大陆）作为正式入口；
- GitHub Pages 作为正式后台部署；
- Vercel 作为正式入口；
- 任何中国大陆访问不稳定的海外部署方案。

- 是否记录真实 `updated_by`；
- 是否增加最小操作日志；
- 是否做保存冲突提示；
- 是否做基础角色权限；
- 是否限制报告导出权限。

此任务影响鉴权和数据结构，建议先做方案讨论，不要直接编码。

### 优先级 4：报告持久化与版本化预研

若领导希望报告可归档、可定稿、可追溯，应预研：

- 是否新增 `assessment_reports` 表；
- 是否保存 `report_content` JSON；
- 是否启用 `report_generated_at`；
- 是否保存 PDF 文件本身；
- 是否需要律师审核状态；
- 用户端开放报告前是否必须完成定稿机制。

当前不建议立即开发，除非业务上明确要求。

### 优先级 5：前台正式上线前体验复核

正式上线前建议复核：

- 首页文案；
- 测评说明；
- 结果页留资引导；
- 企业微信二维码；
- 简洁版结果图导出；
- `submission_source` 正式取值；
- 移动端访问体验；
- 中国大陆访问与提交稳定性。

### 优先级 6：依赖安全检查与维护

建议单独开小任务处理：

- 查看 `npm audit` finding；
- 判断风险等级；
- 判断是否可通过小版本升级解决；
- 避免盲目强制升级；
- 验证升级后 PDF / PNG 导出不受影响。
